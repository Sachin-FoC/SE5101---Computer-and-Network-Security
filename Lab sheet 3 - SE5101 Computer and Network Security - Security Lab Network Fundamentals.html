Lab Sheet 03: Security Lab & Network Fundamentals

Duration: 2–3 hours  |  Environment: VirtualBox / VMware with Kali Linux + Target VM(s)  |  Mode: Individual / Pair

1. Learning Outcomes

By the end of this lab, students will be able to:
  • Set up and configure a Kali Linux attacker VM and a target VM in a virtualized lab environment.
  • Explain the difference between NAT and Host-Only networking modes and configure both.
  • Assign, verify, and troubleshoot static and dynamic IP configurations on Linux hosts.
  • Use core networking commands (ping, ip, ss, netstat) to inspect connectivity, interfaces, and active connections.
  • Identify open ports and running network services on a host and relate them to potential attack surfaces.

3. Background Reading

NAT (Network Address Translation) mode: The VM shares the host's IP address to reach external networks (e.g. the internet). The host acts as a router and performs address translation. VMs on NAT typically cannot be reached directly from the host or from other VMs unless port forwarding is configured.

Host-Only networking: Creates a private virtual network shared only between the host machine and the VMs attached to it. There is no route to the external internet. This is the safest mode for practising attacks between an attacker VM and a target VM, since traffic never leaves the host.

Why this matters for security labs: Isolating the attacker and target on a Host-Only network guarantees that scanning/exploitation traffic cannot accidentally reach real-world systems.

4. Lab Tasks

1Import and Boot the VMs
  1. Open your hypervisor and import the Kali Linux VM (File → Import Appliance, if using an OVA).
  2. Import or create the target VM (e.g. Metasploitable2) in the same hypervisor.
  3. Allocate at least 2 GB RAM and 2 CPU cores to the Kali VM; 512 MB–1 GB RAM is sufficient for the target VM.
  4. Start both VMs and log in:
    • Kali Linux default credentials: kali / kali (verify with your image documentation).
    • Metasploitable2 default credentials: msfadmin / msfadmin.
2Configure Host-Only Networking
  1. In VirtualBox: go to File → Host Network Manager and create a Host-Only adapter (e.g. vboxnet0) if one does not already exist. Note its subnet (e.g. 192.168.56.0/24).
  2. For both the Kali VM and the target VM: open Settings → Network, and set Adapter 1 to Host-Only Adapter, selecting the adapter created above.
  3. Restart both VMs so the new network setting takes effect.

3Add a Second Adapter for NAT (Internet Access)
  1. On the Kali VM only, go to Settings → Network → Adapter 2, enable it, and set it to NAT. This gives Kali internet access for updates while Adapter 1 (Host-Only) is used to talk to the target.
  2. Boot Kali and confirm you now have two interfaces (one for NAT, one for Host-Only) using the command in Task 4.
Why two adapters? Separating NAT (internet/updates) from Host-Only (isolated lab traffic) mirrors real penetration-testing setups where the attack traffic is kept off the general network.
4Inspect and Configure IP Addressing

On the Kali VM, open a terminal and run:

ip addr show
# or shorthand
ip a

Identify the interface connected to the Host-Only network (commonly eth1 or enp0s8) and note its IP address.

If the interface has no IP address (no DHCP on Host-Only), assign one manually:

sudo ip addr add 192.168.56.101/24 dev eth1
sudo ip link set eth1 up

Repeat on the target VM to confirm/assign an IP in the same subnet, e.g. 192.168.56.102/24.

Verify routing table and default gateway:

ip route show

8Basic Port & Service Reconnaissance

From Kali, check whether a specific port on the target is reachable using ping (ICMP only, not port-specific) and a simple TCP connection test:

ping -c 2 192.168.56.102
nc -zv 192.168.56.102 21-25
nc -zv 192.168.56.102 80

nc -zv (netcat) attempts a zero-I/O connection to each port in the given range and reports open/closed — this gives you a first taste of port scanning, which will be covered formally with nmap in the next lab.
