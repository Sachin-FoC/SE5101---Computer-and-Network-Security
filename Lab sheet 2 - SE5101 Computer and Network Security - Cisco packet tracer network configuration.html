Cisco Network Configuration & Troubleshooting

A guided Cisco Packet Tracer practical covering topology design, switching, VLANs, trunking, inter-VLAN routing, DHCP, static routing, OSPF, ACLs and packet simulation.

Duration: 3 HoursSoftware: Cisco Packet TracerBeginner → Intermediate
Lab contents Learning Outcomes Basic Network Switches VLANs Inter-VLAN Routing DHCP Static Routing OSPF ACL Simulation Final Challenge

1. Learning Outcomes

By the end of this practical, students should be able to:

  1. Identify and connect common network devices.
  2. Configure basic Cisco switch settings.
  3. Configure VLANs and access ports.
  4. Configure trunk links.
  5. Configure inter-VLAN routing.
  6. Configure DHCP.
  7. Configure static routing.
  8. Configure OSPF.
  9. Configure a basic ACL.
  10. Examine packet movement using Packet Tracer Simulation Mode.
  11. Verify and troubleshoot network connectivity.

5. Configure Trunking & Inter-VLAN Routing

Concept: An access port normally carries one VLAN. A trunk can carry traffic for multiple VLANs.

5.1 Configure the SW1-to-R1 Link as a Trunk

Assume SW1 Fa0/24 connects to R1 G0/0.

configure terminal

interface fa0/24
switchport mode trunk
exit

Verify:

show interfaces trunk

5.2 Configure Router-on-a-Stick on R1

Enable the physical interface:

enable
configure terminal
hostname R1

interface gigabitEthernet 0/0
no shutdown
exit

Create the VLAN 10 subinterface:

interface gigabitEthernet 0/0.10
encapsulation dot1Q 10
ip address 192.168.10.1 255.255.255.0
exit

Create the VLAN 20 subinterface:

interface gigabitEthernet 0/0.20
encapsulation dot1Q 20
ip address 192.168.20.1 255.255.255.0
exit

Verify:

show ip interface brief

5.3 Test Inter-VLAN Communication

From PC1:

ping 192.168.10.20
ping 192.168.20.10
Q1. Why can PC1 communicate with PC2 without a router?
Q2. Why is a router required for PC1 to communicate with PC3?
Q3. What is the default gateway of PC1?
Q4. What is the purpose of encapsulation dot1Q 10?

6. Configure DHCP

Configure R1 as a DHCP server. First change the PCs to DHCP using Desktop → IP Configuration → DHCP.

enable
configure terminal

ip dhcp excluded-address 192.168.10.1
ip dhcp excluded-address 192.168.20.1

ip dhcp pool STUDENTS
network 192.168.10.0 255.255.255.0
default-router 192.168.10.1
dns-server 8.8.8.8
exit

ip dhcp pool STAFF
network 192.168.20.0 255.255.255.0
default-router 192.168.20.1
dns-server 8.8.8.8
exit

Verify:

show ip dhcp binding
Expected result: PCs should automatically receive addresses from their respective DHCP pools.

7. Router-to-Router Connectivity & Static Routing

Connect R1 to R2. Use:

InterfaceAddress
R1 G0/110.0.0.1/30
R2 G0/110.0.0.2/30

7.1 Configure R1

enable
configure terminal

interface gigabitEthernet 0/1
ip address 10.0.0.1 255.255.255.252
no shutdown
exit

7.2 Configure R2

enable
configure terminal
hostname R2

interface gigabitEthernet 0/1
ip address 10.0.0.2 255.255.255.252
no shutdown
exit

Test:

R1# ping 10.0.0.2
R2# ping 10.0.0.1

7.3 Configure R2 LAN

interface gigabitEthernet 0/0
ip address 192.168.30.1 255.255.255.0
no shutdown
exit

On R1, add a route to R2's LAN:

ip route 192.168.30.0 255.255.255.0 10.0.0.2

On R2, add routes back to the VLAN networks:

ip route 192.168.10.0 255.255.255.0 10.0.0.1
ip route 192.168.20.0 255.255.255.0 10.0.0.1

Verify:

show ip route

Look for routes marked S. These are static routes.

8. Configure OSPF

Now replace manually configured inter-router routing with OSPF.

8.1 R1

enable
configure terminal

router ospf 1
network 192.168.10.0 0.0.0.255 area 0
network 192.168.20.0 0.0.0.255 area 0
network 10.0.0.0 0.0.0.3 area 0
exit

8.2 R2

enable
configure terminal

router ospf 1
network 192.168.30.0 0.0.0.255 area 0
network 10.0.0.0 0.0.0.3 area 0
exit

Verify OSPF:

show ip ospf neighbor
show ip route
show ip protocols
Expected: show ip ospf neighbor should show the neighboring router, and learned routes should appear with an O code.

9. Configure an Access Control List

Security requirement: Students in 192.168.10.0/24 must not be allowed to access the staff network 192.168.20.0/24.

enable
configure terminal

access-list 100 deny ip 192.168.10.0 0.0.0.255 192.168.20.0 0.0.0.255
access-list 100 permit ip any any

Apply the ACL to the VLAN 10 interface:

interface gigabitEthernet 0/0.10
ip access-group 100 in
exit

Test from PC1:

ping 192.168.20.10

The ping should fail.

Then test another permitted destination, such as the R2 LAN:

ping 192.168.30.10

Verify ACL counters:

show access-lists
Observe: The packet counters should increase when traffic matches an ACL rule.

10. Packet Tracer Simulation Mode

Switch from Realtime to Simulation.

Create a simple test such as:

PC1 ───── ping ─────> PC2

Use Capture / Forward to move the packet through the network. Open the packet details and investigate the protocol layers.

Ethernet

  • Source MAC address
  • Destination MAC address
  • EtherType

IPv4

  • Source IP address
  • Destination IP address
  • TTL
  • Protocol

ICMP

  • Echo Request
  • Echo Reply

Compare Layer 2 and Layer 3 Communication

Capture:

PC1 → PC2

Then capture:

PC1 → PC3
Q1. Are PC1 and PC2 in the same VLAN?
Q2. When PC1 communicates with PC3, does the packet need to pass through R1?
Q3. What happens to the destination MAC address when traffic passes through a router?
Q4. Does the destination IP address normally change when the packet is routed?

13. Learning Approach

BUILD ↓ CONFIGURE ↓ VERIFY ↓ OBSERVE ↓ BREAK / APPLY A SECURITY CONTROL ↓ TROUBLESHOOT ↓ VERIFY AGAIN

The objective is not to memorize Cisco commands. For every command, students should understand what network behavior it creates, how to verify it, and how to diagnose it when it fails.

Connection to the next practical: Packet Tracer teaches the logical behavior of switches, routers, VLANs and routing. A subsequent Wireshark practical can use Kali/Ubuntu VMs to capture real Ethernet, ARP, ICMP, TCP, UDP, DNS and HTTP traffic and analyze the same concepts using real packets.
