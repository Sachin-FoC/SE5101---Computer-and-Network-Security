SE5101 – Computer and Network Security

Lab Sheet 04: Network Traffic Analysis with Wireshark

Duration: 2.5–3 hours  |  Environment: Kali Linux VM + one Target/Peer VM (Host-Only network)  |  Mode: Individual / Pair  |  Level: Beginner (no prior Wireshark experience assumed)

1. Learning Outcomes

By the end of this lab, students will be able to:
  • Capture live network traffic using Wireshark on a Kali Linux VM.
  • Identify and interpret Ethernet (Layer 2), IP (Layer 3), and TCP (Layer 4) header fields inside a captured packet.
  • Recognize and explain the TCP three-way handshake (SYN, SYN-ACK, ACK) in a capture.
  • Analyze DNS query/response traffic and HTTP request/response traffic.
  • Use "Follow TCP Stream" to reconstruct a full conversation between two hosts.
  • Write and apply Wireshark display filters to isolate traffic of interest.

2. Pre-Lab Setup

  • ☐ Kali Linux VM and a second VM (target/peer) both running and connected on the same Host-Only network (see Lab Sheet 03).
  • ☐ Confirm both VMs can ping each other before starting.
  • ☐ Wireshark is pre-installed on Kali. Verify with: 
    wireshark --version
    If not installed: 
    sudo apt update && sudo apt install wireshark -y
  • ☐ Allow non-root capture (only needed once): 
    sudo usermod -aG wireshark $USER
    Then log out and log back in for the group change to apply.
⚠ Ethics Notice: Only capture traffic on the isolated Host-Only lab network between your own VMs. Never run Wireshark on university Wi-Fi, shared networks, or any network you do not have permission to monitor. Capturing other people's traffic without consent is illegal in most jurisdictions.

3. Background: What Wireshark Shows You

Wireshark captures raw frames off a network interface and decodes them layer by layer. Each row in the packet list represents one frame, and expanding it in the packet details pane reveals a nested structure:

LayerProtocol ExampleWhat to look for
Layer 2 – Data LinkEthernet IISource/Destination MAC address, EtherType
Layer 3 – NetworkIP (IPv4)Source/Destination IP, TTL, Protocol field, header checksum
Layer 4 – TransportTCP / UDPSource/Destination port, Sequence/ACK numbers, Flags, Window size
Layer 7 – ApplicationDNS, HTTPQuery names, HTTP methods, status codes, payload data

4. Lab Tasks

1Launch Wireshark and Start a Capture
  1. On Kali, open Wireshark: Applications → Sniffing & Spoofing → Wireshark, or run in terminal: 
    sudo wireshark
  2. You will see a list of available interfaces (e.g. eth0, eth1). Select the interface connected to the Host-Only network (the one sharing a subnet with your second VM — check with ip a if unsure).
  3. Double-click the interface, or select it and click the blue shark-fin Start button, to begin capturing.
  4. You should now see packets streaming into the packet list pane in real time.
Tip: The Wireshark window has three panes: Packet List (top), Packet Details (middle, expandable tree), and Packet Bytes (bottom, raw hex/ASCII). Clicking a packet in the top pane updates the other two.
2Generate Traffic to Capture

While the capture is running, generate some traffic from a terminal on Kali (or the second VM):

ping -c 4 <other-VM-IP>
curl http://example.com
nslookup example.com

Let it run for about 30 seconds, then click the red Stop button in Wireshark.

6Identify the TCP Three-Way Handshake
  1. Clear the current capture (Ctrl+E to stop if running, then the "x" icon to clear, or just start a fresh capture).
  2. Start capturing again, then from a terminal initiate a fresh connection, e.g.: 
    curl http://example.com
  3. Stop the capture and apply this filter to isolate the handshake for that connection: 
    tcp.port == 80
  4. Locate the first three packets of a new connection. They should show, in order:
StepDirectionFlagsMeaning
1Client → ServerSYNClient requests to open a connection
2Server → ClientSYN, ACKServer acknowledges and agrees to connect
3Client → ServerACKClient confirms; connection established
Record the three handshake packets you found:
Packet #  — SYN  |  Packet #  — SYN,ACK  |  Packet #  — ACK
Tip: You can also find the closing sequence (FIN/ACK exchange, sometimes a 4-way teardown) later in the same stream — note its packet numbers too if visible.
7Analyze DNS Traffic
  1. Apply the filter: 
    dns
  2. If you don't see any DNS packets, generate some: 
    nslookup github.com
dig google.com
  3. Click a DNS Query packet (Info column shows "Standard query"). Expand "Domain Name System (query)" and note the fields.
  4. Click the matching DNS Response packet (Info column shows "Standard query response"). Expand it to see the resolved IP address(es).
Domain queried:     Query Type (A/AAAA/MX etc.):

8Analyze HTTP Traffic
  1. Apply the filter: 
    http
  2. If empty, generate HTTP traffic (not HTTPS, since that is encrypted): 
    curl http://neverssl.com
  3. Find an HTTP Request packet (Info column shows "GET /...") and expand "Hypertext Transfer Protocol". Note the request method, host, and user-agent.
  4. Find the matching HTTP Response and note the status code (e.g. 200 OK, 404 Not Found) and content type.

Note: Most modern websites use HTTPS (TLS-encrypted), so you will only see the TLS handshake, not readable HTTP content, for those. Use plain http:// sites like neverssl.com or example.com for this exercise.
9Follow a TCP Stream
  1. Right-click any packet that is part of an HTTP conversation.
  2. Select Follow → TCP Stream from the context menu.
  3. A new window opens showing the full reconstructed conversation: client requests in one color (typically red), server responses in another (typically blue).
  4. Read through the reconstructed HTTP request/response. Close the window when done — notice that Wireshark automatically applies a filter like tcp.stream eq X to the main window.

10Apply Wireshark Display Filters

Type each filter below into the filter bar (top of window) and press Enter. Record how many packets match and briefly describe what you see.

FilterPurpose# Packets Matched
ip.addr == <target-IP>All traffic to/from a specific host 
ip.src == <IP>Traffic originating from a specific host 
tcp.port == 80All traffic on port 80 (HTTP) 
tcp.flags.syn == 1 && tcp.flags.ack == 0Only SYN packets (connection attempts) 
icmpOnly ICMP (ping) traffic 
dnsOnly DNS traffic 
http.requestOnly HTTP request packets 
http.response.code == 200Only successful HTTP responses 
tcp.analysis.retransmissionRetransmitted TCP packets (possible network issues) 
Tip: Display filters (typed in the top bar) narrow what you see without discarding captured data. Capture filters (set before starting a capture, e.g. host 192.168.56.102) narrow what is recorded in the first place. This lab only uses display filters.
